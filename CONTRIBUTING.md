# Работа над Forme

## Локальный запуск

1. Установите Node.js из `.nvmrc`.
2. Выполните `npm ci`.
3. Скопируйте `.env.example` в `.env.local` и заполните только локальные секреты.
4. Запустите `npm run dev`.

## Перед передачей изменения

- Выполните `npm run check`.
- Убедитесь, что новый код следует `docs/CODE_ORGANIZATION.md`; архитектурные границы и размеры файлов проверяются автоматически.
- Для труднообратимого решения сначала создайте ADR из `docs/decisions/0000-template.md`.
- Проверьте светлую и тёмную темы.
- Проверьте ширины около 1440, 1024, 768 и 390 px.
- Для изменений LLM приложите схему ответа, тестовый пример и результат eval.
- Для изменений claims проверьте трассировку до точного источника и сохранение ограничений.
- Обновите соответствующий документ в `docs/`.

## Структура изменения

- Добавляйте пользовательский сценарий в собственный `features/<name>` и экспортируйте только его публичный API.
- Помещайте бизнес-инварианты в `lib/domain`, orchestration и ports — в `lib/application`, vendor adapters — в `lib/infrastructure`.
- Делите код по причинам изменения до достижения hard limits: 250 строк на файл и 120 строк на функцию или компонент.
- Не создавайте общие файлы `utils`, `helpers` или `common`; давайте модулю предметное имя.

## Секреты и данные

API-ключи хранятся только в локальных или хостинговых секретах. В репозиторий нельзя добавлять ключи, полные тексты закрытых статей, персональные данные и реальные пользовательские запросы без обезличивания.
