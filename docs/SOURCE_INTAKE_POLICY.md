# Политика отбора источников

Статус: `source-intake-v1`. Это детерминированный pre-screen до LLM и до научной оценки.

## Разделение хранилищ

- **История поиска** хранит метаданные всех найденных candidates для воспроизводимости.
- **Исследовательский архив** хранит только фрагменты записей, прошедших intake-gate.
- **База знаний** хранит версии claims и evidence-связи. Публикация в поиске или наличие аннотации не создаёт claim.

## Автоматически допускается только triage

PubMed-запись допускается в исследовательский архив, если одновременно:

1. PMID присутствует и согласован с внутренним идентификатором;
2. запись не отозвана и не имеет `expression_of_concern`;
3. это не editorial, comment, letter, news, biography, interview, erratum/retraction notice или другой заведомо не исследовательский формат;
4. есть аннотация не короче 280 нормализованных символов.

Прошедшая запись получает только статус `admitted_to_triage`. Это разрешает дальнейший отбор и поиск полного текста, но не source assessment, claim или публикацию. Исправленная запись сохраняется с обязательным флагом ручной проверки.

## Что не является автоматическим критерием

- импакт-фактор или известность журнала;
- число цитирований;
- источник финансирования сам по себе;
- положительный или отрицательный результат;
- совпадение отдельных слов в заголовке;
- предпочтительность результата для будущего контента.

Эти признаки либо не измеряют достоверность, либо создают риск selection bias. Релевантность вопросу, дизайн, внутренняя валидность, статистика и применимость оцениваются позже и отдельно.

## Причины отказа и аудит

Для каждого PubMed-кандидата сохраняются версия policy, решение, причины, record status, publication types, длина аннотации и время проверки. Отклонённая запись не получает `source_chunks`, но остаётся в истории поиска с метаданными и может быть пересмотрена человеком в будущем.

## Следующие автономные этапы без LLM

1. Подключить разрешённые полные тексты PubMed Central Open Access и проверку полноты секций.
2. Сделать отдельную очередь source review с ручным include/exclude и обязательной причиной override.
3. Добавить периодическую перепроверку corrections, expressions of concern и retractions.
4. Реализовать lexical search по source metadata/chunks и каноническим claims до подключения embeddings.
5. Добавить ручное создание и утверждение claim с полной трассировкой.
6. Перевести архив контента, статусы и календарь из демонстрационных данных в D1.

Этапы, которые всё равно потребуют участия владельца: добавление LLM secret, экспертная калибровка evidence-методологии и формирование авторского style profile.
