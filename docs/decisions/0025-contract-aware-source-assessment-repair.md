# ADR-0025: Contract-aware repair научной оценки

- Статус: принято
- Дата: 2026-09-07
- Владельцы: Forme
- Уточняет: ADR-0024 «Ограниченное восстановление source assessment»

## Контекст

Продовый прогон релевантных full-text источников показал два повторяемых fail-closed отказа. Оба ответа исчерпали единственный repair-проход из-за неверного design-specific набора `integrityChecks`. Общая категория `invalid_model_output` не сообщала repair-вызову, какой именно пункт строгого runtime-контракта нарушен, поэтому модель могла повторить ту же ошибку.

## Решение

Оставить ровно один repair-проход и неизменный строгий контракт. Repair получает только безопасный идентификатор нарушенного раздела контракта. Если первый структурированный черновик содержит допустимый `studyDesign`, для ошибки `integrity_checks` дополнительно передаётся точный упорядоченный перечень обязательных проверок этого дизайна. Для ошибок dimensions и reader brief передаётся короткое точное напоминание. Черновик ответа, исходный полный текст и другие потенциально чувствительные данные в repair-инструкцию не копируются.

## Последствия

- Научные gates, provenance и число retry не ослабляются.
- Повтор становится направленным и менее склонным воспроизводить ту же структурную ошибку.
- Любой второй невалидный ответ по-прежнему отклоняется целиком и не создаёт индекс доверия.
- Версия prompt и audit trail позволяют отделить новые результаты от прежнего поведения.

## Проверка

Контрактный тест моделирует неверный набор design-specific проверок и требует, чтобы повтор получил точный issue, количество, порядок и допустимые passage aliases. Продовый smoke-прогон должен подтвердить успешную оценку ранее отказавших источников без ручного подтверждения evidence gate.
