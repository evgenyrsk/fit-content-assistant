# ADR-0011: Личный Meta Development Mode как рабочий контур

- Статус: принято
- Дата: 2026-08-28
- Владельцы: Forme
- Уточняет: ADR-0010

## Контекст

Forme остаётся персональным продуктом: Threads использует только владелец, добавленный в роли Meta-приложения. Публичный App Review, Business Verification и Access Verification создают существенную операционную нагрузку, но не дают ценности однопользовательскому сценарию.

## Критерии решения

- рабочий поиск Threads для владельца без публичного OAuth;
- минимальная поверхность доступа и отсутствие токена в браузере;
- понятная диагностика отзыва, истечения и временной недоступности;
- отсутствие ложной зависимости личного режима от публикации приложения;
- возможность позже перейти к публичному режиму отдельным решением.

## Рассмотренные варианты

1. **Сразу завершить публичный App Review.** Отклонено до появления других пользователей.
2. **Удалить Threads-интеграцию.** Отклонено: текущий личный доступ уже работает и полезен Trend Scout.
3. **Оставить Development Mode для app-role аккаунта.** Выбрано как минимальная рабочая схема.

## Решение

Публичный App Review и обе verification-процедуры отложены. Черновик не отправляется, приложение не переводится в Live Mode. Серверный токен владельца остаётся единственным credential; интерфейс проверяет доступ через профильный endpoint и показывает безопасный нормализованный статус без raw Meta errors и секрета.

Дата окончания доступа хранится отдельно в `THREADS_TOKEN_EXPIRES_AT` как необязательные операционные метаданные. Автоматическое обновление токена пока не выполняется: до появления надёжного credential store и проверенного refresh-процесса доступ заменяется вручную как server-only secret.

## Последствия и риски

- Threads работает только для аккаунтов с ролью в приложении.
- Отзыв или истечение доступа останавливает Threads-сигналы, но не другие источники.
- Неизвестная дата окончания не блокирует работу; интерфейс просит зафиксировать её при следующей ротации.
- Tech Provider остаётся активным, но не обязывает завершать публичную проверку сейчас.

## Проверка и пересмотр

Решение пересматривается перед подключением второго пользователя, публичным OAuth, публикацией через API или отправкой App Review. Тогда требуется отдельное решение по encrypted credential storage, rotation и deletion lifecycle.
