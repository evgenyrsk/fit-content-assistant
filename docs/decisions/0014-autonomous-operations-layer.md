# ADR-0014: Автономный operations-слой без LLM

- Статус: принято
- Дата: 2026-08-28
- Владельцы: владелец продукта, Forme engineering
- Заменяет: —

## Контекст

До подключения LLM Forme уже хранит реальные источники, claims и content items. Продукту не хватало самостоятельного контура ежедневной работы: обслуживания актуальности, ручного контента, календаря, банка тем, личных заметок и метрик. Эти функции не должны зависеть от модели или ослаблять evidence-gates.

## Критерии решения

- весь постоянный продуктовый state хранится в D1;
- raw evidence и approved claims не смешиваются в поисковой выдаче;
- ручной контент сохраняет трассировку и проходит отдельный human fact-check;
- редакционный статус не подменяет научный gate;
- тренды, личный опыт и метрики не повышают scientific confidence;
- система полезна без внешнего LLM-ключа.

## Рассмотренные варианты

1. Ждать LLM и строить операции после генерации. Отклонено: блокирует независимые функции и связывает доменную модель с провайдером.
2. Хранить календарь, темы и метрики в браузере. Отклонено: нет канонической истории, аудита и переносимости.
3. Добавить отдельный provider-neutral operations-слой поверх D1. Принято.

## Решение

Добавлены независимые сущности `content_operations`, `content_item_versions`, `content_human_reviews`, `topic_ideas`, `user_notes` и `publication_metrics`. Lexical search выполняет две отдельные выборки: latest claim versions и source chunks. Source chunk получает явный admissibility-признак, но никогда не отображается как claim.

Ручной content item создаётся как `needs_review / draft`. Approval требует трёх явных подтверждений и повторной проверки всех связанных latest approved claims. Только после этого разрешены `ready → scheduled → published`. Ссылка на публикацию обязательна; метрики сохраняются как snapshots и используются только для content intelligence.

Просроченные PubMed-записи перепроверяются один раз за открытую браузерную сессию и остаются доступны для ручного запуска. Постоянный cron сознательно не имитируется внутри web-приложения.

## Последствия и риски

Ежедневная работа больше не зависит от LLM. Возникает дополнительная операционная схема и набор переходов, которые необходимо покрывать миграциями и contract tests. Session-based revalidation не заменяет фоновый scheduler, когда приложение закрыто.

## Проверка и пересмотр

`npm run check` блокирует release при нарушении переходов, claim-трассировки, CSV-контракта или регрессионных evidence fixtures. Решение пересматривается при появлении многопользовательских ролей, фонового scheduler или измеримого semantic retrieval.
