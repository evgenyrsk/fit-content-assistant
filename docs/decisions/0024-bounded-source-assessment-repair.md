# ADR-0024: Ограниченное восстановление source assessment

- Статус: принято
- Дата: 2026-09-02
- Владельцы: Forme
- Заменяет: —

## Контекст

Живой прогон трёх разрешённых полных текстов показал, что review-модель может вернуть неполный или не соответствующий runtime-контракту JSON даже при переданной strict schema. Fail-closed gate корректно отклоняет такой ответ, но единичная структурная ошибка делает весь пользовательский сценарий хрупким.

## Критерии решения

- Нельзя ослаблять схему, provenance или evidence gate.
- Повтор должен быть ограниченным и наблюдаемым.
- Ошибка провайдера не должна запускать дорогой бесконтрольный retry.
- Максимальный бюджет не должен менять фактическую стоимость успешно завершившегося короткого ответа.

## Рассмотренные варианты

- Принимать частичный JSON: отклонено, поскольку создаёт неполную научную оценку.
- Повторять без ограничений: отклонено из-за стоимости и непредсказуемости.
- Один repair-проход только для невалидного контракта или provenance: выбран.

## Решение

Source assessment получает до 7200 output tokens в экономном профиле и до 9000 в сбалансированном. При первой ошибке strict runtime contract или неизвестном passage alias выполняется ровно один повтор с указанием категории ошибки и требованием заново проверить полный контракт. Provider/network errors не повторяются. Успешный repair отмечается в `model_runs.tool_calls` как `structured_output_retry`.

## Последствия и риски

Типичная успешная оценка не становится дороже, поскольку оплачивается фактический вывод. Ошибочный первый ответ может удвоить стоимость одного assessment. Даже после repair любой невалидный результат по-прежнему закрывает gate и не создаёт индекс доверия.

## Проверка и пересмотр

Контрактные тесты проверяют успешный одноразовый repair и отсутствие retry при provider error. Решение пересматривается, если доля repair остаётся высокой на живом eval-наборе или появляется модель с надёжным native strict output.
